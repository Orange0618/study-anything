# {{TITLE}}学习工作台使用文档

创建日期：{{DATE}}

本文件是新 Agent 接手本学习项目时的第一入口，说明项目架构、各目录含义、状态规则和维护协议。

## 1. 项目用途

本项目用于把领域知识转化为经过审查的教学模块、可执行实践、可检查证据和可持续接手的学习记录。

## 2. Agent 接手顺序

1. 阅读本使用文档。
2. 阅读根目录 `学习进度表.md`。
3. 定位当前模块并阅读其 `README.md`。
4. 阅读当前模块 `审查/` 中最新审查报告。
5. 阅读根目录 `reviews/` 中最新相关学习 Review。
6. 检查进度表引用的测试与证据。
7. 汇报当前目标、模块状态、已验证结果、阻塞和唯一下一步。

不要仅依赖前序对话记忆恢复状态。

## 4. 文件与目录含义

- `学习进度表.md`：当前全局状态和唯一追溯入口。
- `调研/`：领域认知、学习深度选项和资料来源。
- `环境/`：安装、依赖、设备、版本和验证结果。
- `modules/`：经过编写、审查、实践和验收的教学模块。
- `modules/<模块>/审查/`：教学质量的初审、修订和复审记录。
- `reviews/`：用户实际学习、验收、阻塞、认知变化和范围调整记录。
- `capstone/`：在前置模块学完后启动的综合项目。

## 5. 模块状态

```text
规划中 → 编写中 → 待审查 → 待修订 → 复审中 → 可学习 → 学习中 → 已学习
```

特殊状态：`已阻塞`、`已暂停`。

- `可学习` 要求独立审查通过。
- `已学习` 要求验收通过、证据存在并创建学习 Review。

## 6. 教学模块审查

主 Agent 编写初稿后，将模块标记为 `待审查`，再调用独立审查子 Agent。审查报告写入模块自己的 `审查/`，主 Agent 根据报告修订；存在阻断或重大问题时必须由新的审查者复审。

教学审查报告不得放入根目录 `reviews/`。

## 7. 学习 Review

根目录 `reviews/` 只记录用户实际学习事件。学习任务变为完成时，必须同时存在证据和学习 Review，并从进度表与模块 README 链接。

## 8. 状态一致性

模块 README 和 `学习进度表.md` 必须保持相同模块状态。发生冲突时，先检查证据和最新审查，再同步修正两个入口；学习进度发生变化时创建相应 Review。

## 9. 禁止事项

- 不创建 roadmap。
- 不以观看时长、课程数量或笔记页数证明掌握。
- 不让主 Agent 的同上下文自检冒充独立子 Agent 审查。
- 不把未通过审查的模块标为可学习。
- 不把缺少证据和学习 Review 的模块标为已学习。
- 不静默覆盖用户已有文件或结构。

## 10. 快速检查

- 当前模块 README 是否声明状态？
- 可学习模块是否有通过的独立审查报告？
- 已学习模块是否有证据和根目录学习 Review？
- 总进度表与模块 README 是否一致？
- 所有相对链接是否存在？
- 是否只保留一个明确下一步？
